# 1. Purpose

This document establishes the one-hundred-and-thirty-seventh document in the MFM v1.2 Steady-State series.

It follows MFM v1.2-Steady-State-136 – Enterprise Application Architecture & Application Operations, Application Governance, Application Portfolio, Application Lifecycle, Application Development, Application Integration, APIs, Application Security, Application Performance, Application Monitoring, Application Resilience, Application Release, Application Support & Application Assurance.

The purpose is to establish the permanent enterprise operating model for data strategy, data governance, data architecture, data ownership, data classification, data lifecycle, data quality, master data, reference data, metadata, data integration, data security, data privacy, data platforms, data resilience, data retention, data suppliers, data compliance, data exceptions, remediation, data assurance, metrics, dashboards, maturity and continual enterprise data capability improvement.

The central objective is:

> **MFM must govern enterprise data as a controlled, trusted, secure, appropriately accessible and lifecycle-managed enterprise asset that supports business processes, decision-making, applications, services, reporting, analytics, compliance and operational continuity.**

# 3. Data Governance Objective

The primary objective is:

> **Establish clear authority, ownership, stewardship, standards, controls, lifecycle requirements, security requirements and assurance for enterprise data.**

# 4. Data Architecture Objective

The primary objective is:

> **Provide coherent data structures, flows, platforms and relationships supporting business capabilities, applications, reporting, analytics, integration and operational services.**

# 5. Data Management Objective

The primary objective is:

> **Ensure data is accurate, complete, timely, consistent, accessible, protected, traceable and appropriately retained throughout its lifecycle.**

# 6. Data Quality Objective

The primary objective is:

> **Ensure data quality is defined, measured, monitored and improved according to business requirements and data criticality.**

# 7. Data Security Objective

The primary objective is:

> **Protect data against unauthorized access, disclosure, alteration, loss, destruction and inappropriate use throughout its lifecycle.**

# 8. Data Privacy Objective

The primary objective is:

> **Ensure personal and otherwise protected data is processed lawfully, fairly, transparently and according to applicable privacy and protection requirements.**

# 9. Data Resilience Objective

The primary objective is:

> **Ensure critical data remains available, recoverable, intact and usable following infrastructure, application, operational, security or other disruptive events.**

# 10. Data Assurance Objective

The primary objective is:

> **Provide reliable evidence that data governance, quality, security, privacy, lifecycle, resilience and management controls operate effectively.**

# 100. Definition of Ready

A data architecture, data domain, data model, master-data arrangement, reference-data service, metadata capability, data integration, data-sharing arrangement, data-security control, privacy control, data platform, quality rule, retention schedule, recovery plan, supplier decision, exception, remediation or assurance review is Ready when purpose, owner, scope, dependencies, classification, criticality, quality requirements, security requirements, privacy requirements, lifecycle requirements, resilience requirements, recovery requirements, risk, approval authority and acceptance criteria are defined.

> **Data architecture must provide coherent, interoperable, traceable, secure, resilient and maintainable data structures, flows and platforms supporting enterprise business capabilities and services.**

# 104. Final Ownership Principle

> **Material data must have accountable business ownership and appropriate stewardship regardless of where the data is hosted, processed, shared or stored.**

# 105. Final Quality Principle

> **Data quality must be defined by business need, measured through explicit rules and continuously improved according to data criticality and risk.**

# 106. Final Security Principle

> **Data security must protect confidentiality, integrity and availability through classification, least privilege, encryption, monitoring, controlled sharing and lifecycle management.**

# 107. Final Privacy Principle

> **Personal and otherwise protected data must be processed according to applicable privacy requirements, with purpose, access, retention, transparency and disposal appropriately controlled.**

# 108. Final Resilience Principle

> **Critical data must remain available, recoverable, intact and usable following infrastructure, application, operational, security or other disruptive events.**

# 109. Final Lifecycle Principle

> **Data must be actively managed from creation or acquisition through use, sharing, archiving, retention and secure disposal.**

# 110. Final Assurance Principle

> **Material data controls and services must be supported by reliable evidence and periodically assessed through risk-based assurance.**

# 111. Final Improvement Principle

> **Data quality issues, security findings, privacy risks, integration failures, recovery results, retention issues, supplier issues and assurance findings must continuously improve MFM's data capability.**

# 112. Final Enterprise Data Integration Principle

> **Data Architecture and Data Management must integrate with Enterprise Architecture, Business Architecture, Applications, Identity, Integration, Infrastructure, Network, Cloud, Cybersecurity, Service Management, Configuration Management, Asset Management, Suppliers, Finance, Risk, Compliance, Legal and Business Continuity.**
