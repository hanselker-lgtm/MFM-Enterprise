# 1. Purpose

This document establishes the seventy-fifth document in the MFM v1.2 Steady-State series.

It follows MFM v1.2-Steady-State-74 – Enterprise Data Protection, Privacy, Records, Information Governance, Retention & Data Lifecycle Management.

The purpose is to establish the permanent enterprise operating model for application portfolio management, application ownership, application strategy, application lifecycle management, application architecture, software architecture, application development, application configuration, application deployment, application operations, application support, application service management, application availability, application performance, application resilience, application security coordination, application data dependencies, application integrations, application interfaces, application technical debt, application modernization, application rationalization, application retirement, application continuity, application monitoring, application incidents, application problems, application changes, application releases, application testing, application assurance, application findings, application exceptions, application remediation, application metrics, application dashboards, application maturity and continual application improvement.

The central objective is:

> **MFM must manage applications throughout their lifecycle so that business capabilities are supported by secure, reliable, maintainable, cost-effective and appropriately governed application services.**

# 3. Application Management Objective

The primary objective is:

> **Ensure applications remain aligned with business requirements, architecture, security, service levels, cost, risk and lifecycle expectations.**

# 4. Application Portfolio Objective

The primary objective is:

> **Maintain an optimized application portfolio that supports required business capabilities without unnecessary duplication, cost, complexity or risk.**

# 5. Application Lifecycle Objective

The primary objective is:

> **Govern applications from introduction and implementation through operation, modernization and retirement.**

# 6. Application Operations Objective

The primary objective is:

> **Provide application services that meet agreed availability, performance, support and user requirements.**

# 8. Application Architecture Objective

# 93. Definition of Ready

An application, application change, release, architecture decision, modernization initiative, rationalization action, retirement, incident, problem, technical-debt item, assurance review or remediation item is Ready when purpose, owner, scope, business capability, dependencies, risk, security, data, architecture, financial implications, acceptance criteria and evidence requirements are defined.

# 94. Definition of Done

An application-management work item is Done when:

```text
Requirement Identified
        ↓
Owner Assigned
        ↓
Application Action Completed
        ↓
Technical / Security / Architecture / Business Validation Completed where Required
        ↓
Documentation Updated
        ↓
Evidence Captured
        ↓
Findings / Exceptions Addressed
        ↓
Outcome Accepted
```
