# 1. Purpose

This document establishes the one-hundred-and-thirty-fourth document in the MFM v1.2 Steady-State series.

It follows MFM v1.2-Steady-State-133 – Enterprise Infrastructure Architecture, Compute, Storage, Virtualization, Operating Systems, Endpoint Infrastructure, Infrastructure Operations, Infrastructure Monitoring, Infrastructure Resilience, Infrastructure Capacity, Infrastructure Security, Infrastructure Lifecycle & Infrastructure Assurance.

The purpose is to establish the permanent enterprise operating model for network strategy, network governance, network architecture, LAN, WAN, internet connectivity, routing, switching, wireless, DNS, DHCP, IP address management, network security, segmentation, remote access, network monitoring, network performance, network capacity, network resilience, network recovery, network lifecycle, network suppliers, network compliance, network exceptions, remediation, network assurance, metrics, dashboards, maturity and continual enterprise network capability improvement.

The central objective is:

> **MFM must govern enterprise networks as secure, resilient, observable and measurable connectivity foundations for business services, applications, data, identity, cloud and operational environments, ensuring that network services are appropriately designed, owned, monitored, protected, maintained, recovered, modernized and retired throughout their lifecycle.**

# 3. Network Governance Objective

The primary objective is:

> **Establish clear authority, ownership, architecture, standards, security controls, operational responsibilities, resilience requirements and assurance for enterprise network services.**

# 4. Network Architecture Objective

The primary objective is:

> **Provide coherent and secure connectivity between users, endpoints, applications, services, data, infrastructure, cloud environments, suppliers and external networks.**

# 5. Network Operations Objective

The primary objective is:

> **Operate network services reliably through disciplined monitoring, maintenance, incident response, change control, configuration management, capacity management and recovery.**

# 6. Network Security Objective

The primary objective is:

> **Protect network services and traffic through segmentation, access control, secure administration, monitoring, encryption where appropriate and layered security controls.**

# 7. Network Resilience Objective

The primary objective is:

> **Ensure critical network services can withstand component, path, site, carrier, equipment and service failures and recover within defined service requirements.**

# 8. Network Capacity Objective

The primary objective is:

> **Ensure network capacity and performance remain sufficient for current and forecast business, application, cloud and service demand.**

# 9. Network Assurance Objective

The primary objective is:

> **Provide reliable evidence that network architecture, operations, security, resilience, capacity and lifecycle controls operate effectively.**

# 115. Final Network Governance Principle

> **MFM must govern enterprise networks as secure, resilient, observable and measurable connectivity foundations for business services, applications, data, identity, cloud and operational environments, ensuring that network services are appropriately designed, owned, monitored, protected, maintained, recovered, modernized and retired throughout their lifecycle.**

# 116. Final Architecture Principle

> **Network architecture must provide secure, segmented, scalable, observable, resilient and recoverable connectivity between enterprise users, services, applications, data, infrastructure, cloud and trusted external parties.**

# 117. Final Security Principle

> **Network security must control connectivity according to identity, trust, service requirements and risk while limiting unnecessary communication and lateral movement.**

# 118. Final Operations Principle

> **Network operations must maintain reliable connectivity through disciplined monitoring, configuration control, change management, capacity management, incident response and recovery.**

# 119. Final Resilience Principle

> **Critical network services must be designed across appropriate failure domains with tested redundancy, alternate paths and recovery capabilities.**

# 120. Final Capacity Principle

> **Network capacity must be continuously aligned with current and forecast demand, application behavior, cloud adoption, remote access and business growth.**

# 121. Final Lifecycle Principle
