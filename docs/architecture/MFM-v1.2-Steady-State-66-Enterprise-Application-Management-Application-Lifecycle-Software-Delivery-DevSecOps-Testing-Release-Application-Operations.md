# 1. Purpose

This document establishes the sixty-sixth document in the MFM v1.2 Steady-State series.

It follows MFM v1.2-Steady-State-65 – Enterprise Data Management, Data Governance, Data Quality, Master Data, Metadata, Data Lifecycle, Analytics & Information Management.

The purpose is to establish the permanent enterprise operating model for application management, application portfolio management, application lifecycle management, software engineering, software delivery, DevSecOps, source-code management, requirements, backlog management, architecture integration, development environments, build management, continuous integration, continuous delivery, testing, quality assurance, security testing, release management, deployment management, application operations, application monitoring, application performance, application support, defect management, technical debt, application resilience, application continuity, application documentation, application assurance, application findings, exceptions, remediation, application metrics, application dashboards, application maturity and continual application improvement.

The central objective is:

> **MFM must maintain secure, reliable, supportable and continuously improving applications through disciplined lifecycle management, controlled software delivery, integrated security, effective testing and stable application operations.**

# 3. Application Management Objective

The primary objective is:

> **Ensure applications remain fit-for-purpose, secure, reliable, maintainable, supportable and aligned with business and service requirements.**

# 4. Software Delivery Objective

The primary objective is:

> **Deliver software changes predictably, securely and with appropriate quality controls.**

# 5. DevSecOps Objective

The primary objective is:

> **Integrate security, quality, operations and compliance throughout the software delivery lifecycle.**

# 6. Testing Objective

The primary objective is:

> **Provide evidence that applications and changes meet defined functional, technical, security, performance and business requirements.**

# 7. Release Objective

The primary objective is:

> **Introduce application changes into production in a controlled, traceable and recoverable manner.**

# 8. Application Operations Objective

The primary objective is:

> **Maintain stable application operation and restore application services efficiently when disruption occurs.**

# 9. Application Assurance Objective

The primary objective is:

> **Provide evidence that applications and application-management processes operate effectively and remain aligned with approved requirements.**

# 103. Definition of Ready

An application requirement, development item, defect, security item, release, deployment, test, technical-debt item, exception or remediation item is Ready when scope, owner, application, dependencies, requirements, risk, acceptance criteria, test requirements, security requirements and evidence requirements are defined.

# 104. Definition of Done

        ↓

        ↓

        ↓

        ↓
