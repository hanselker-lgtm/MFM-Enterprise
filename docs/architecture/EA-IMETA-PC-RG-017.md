## Purpose
Establish the authoritative mandatory-monitoring layer defining how accepted and relied-upon mandatory states are continuously or periodically observed so that deterioration, regression, material change, threshold breach or loss of validity is detected within required time.

## Core Principle
Monitoring is the operational sensing layer that protects reliance. Monitoring shall be designed around the risk, required state, materiality and detection time of the governed condition. Monitoring shall not become a substitute for reassessment or revalidation when those activities are required.

```text
ACCEPTED / RELIED-UPON STATE
      ↓
MONITORING OBJECTIVES
      ↓
INDICATORS / SIGNALS
      ↓
OBSERVE / COLLECT
      ↓
COMPARE WITH BASELINE / THRESHOLD
      ↓
NORMAL / WARNING / BREACH / UNKNOWN
      ↓
ALERT / RESPOND / REASSESS
```

## Monitoring Quality Test
```text
DEFINED STATE
+ MONITORING OBJECTIVE
+ RELEVANT INDICATORS
+ ADEQUATE FREQUENCY
+ SUFFICIENT COVERAGE
+ VALID DATA / EVIDENCE
+ THRESHOLDS
+ ALERTING
+ ACCOUNTABILITY
+ RESPONSE PATH
=
VALID GOVERNED MONITORING
```

## Monitoring Structure

| Element | Required definition |
|---|---|
| Governed State | State being monitored |
| Objective | What monitoring must detect |
| Indicator | Observable signal |
| Frequency | Observation interval |
| Coverage | Scope and dependencies |
| Data Source | Source of observation |
| Baseline | Reference condition |
| Threshold | Decision boundary |
| Alert | Triggered notification/state |
| Owner | Accountable monitoring role |
| Response | Action following material signal |

## Monitoring Objective

The objective shall define the change, degradation, breach, anomaly or regression that monitoring must detect and communicate in time to protect the governed state.

## Monitoring Definition

Monitoring is the controlled observation and evaluation of a governed state over time. It produces signals and evidence; it does not by itself replace formal reassessment or revalidation.

## Monitoring Scope

Scope shall identify systems, services, controls, processes, data, environments, users and dependencies whose state can materially affect reliance.

## Monitoring Authority

Authority shall define who owns monitoring, who may change thresholds, who receives alerts, who initiates response and who may suspend reliance when monitoring indicates material risk.

## Monitoring Indicators

Indicators shall be relevant, measurable where possible and sufficiently sensitive to detect meaningful deterioration without creating unmanageable noise.

## Monitoring Frequency

Frequency shall be based on risk, change rate, detection objective and required response time.

```text
RISK / CHANGE RATE
↓
REQUIRED DETECTION TIME
↓
MONITORING FREQUENCY
```

## Monitoring Coverage

Coverage shall account for material dependencies, failure modes and blind spots. Partial coverage shall be explicitly identified rather than represented as full coverage.

## Monitoring Evidence

Monitoring observations shall be timestamped, attributable and traceable to their source. Material alerts and decisions shall be preserved.

## Monitoring Baseline

Baselines shall represent the approved expected state and shall be versioned. Rebaselining shall not erase evidence of prior regression.

## Monitoring Thresholds

Thresholds shall define normal, warning and breach conditions as appropriate and shall be governed, versioned and effective-dated.

## Monitoring Alerting

Alerting shall route material signals to the appropriate authority within the required time. Alert fatigue shall not justify suppression of mandatory alerts.

```text
OBSERVATION
↓
THRESHOLD / RULE
├── NORMAL → RECORD / CONTINUE
├── WARNING → MONITOR / ACT
└── BREACH → ALERT / RESPOND / REASSESS
```

## Security Monitoring

Security monitoring shall detect relevant changes in exposure, access, vulnerabilities, incidents, controls and security boundaries as applicable.

## Resilience Monitoring

Resilience monitoring shall detect relevant changes in availability, capacity, dependencies, recovery capability, continuity conditions and degraded states.

## Compliance Monitoring

Compliance monitoring shall detect material deviations from applicable requirements, controls, policies, contracts or approved conditions.

## Data Monitoring

Data monitoring shall detect relevant changes in integrity, quality, completeness, lineage, access, retention and authorized-use conditions.

## AI and Agent Monitoring

AI and agent monitoring shall observe relevant changes in authority, policy adherence, tool use, data use, autonomy, outputs, behavioural patterns and safety boundaries.

```text
AI / AGENT OBSERVATION
↓
AUTHORITY / POLICY / TOOL / DATA / BEHAVIOUR
↓
WITHIN BOUNDARY?
├── YES → CONTINUE
└── NO → ALERT / LIMIT / SUSPEND / ESCALATE
```

## Monitoring Failure

Loss, degradation or corruption of monitoring capability is itself a governed condition. A system that cannot observe a critical state shall not be assumed healthy merely because no alert is present.

```text
MONITORING FAILURE
↓
ASSESS BLIND SPOT
↓
LIMIT RELIANCE IF MATERIAL
↓
RESTORE MONITORING / ESCALATE
```

## Monitoring Escalation

Escalation shall occur when a material threshold is breached, monitoring is unavailable, evidence quality is inadequate, coverage is materially incomplete or repeated alerts indicate unresolved regression.

## Monitoring Review and Learning

Monitoring shall be reviewed for false positives, false negatives, blind spots, stale indicators, unsuitable thresholds, inadequate frequency and recurring regression patterns.

## Monitoring Determination Model
```text
OBSERVATION AVAILABLE?
├── NO → MONITORING FAILURE / ASSESS BLIND SPOT
└── YES
     ↓
DATA QUALITY SUFFICIENT?
├── NO → UNKNOWN / ESCALATE
└── YES
     ↓
THRESHOLD / RULE EVALUATED
├── NORMAL → CONTINUE

└── BREACH → ALERT / RESPONSE / REASSESS
```

## Monitoring Anti-Gaming Control
Monitoring shall not suppress, aggregate, delay, redefine or normalize material signals solely to avoid alerts, findings, escalation or operational disruption. Changes to alert logic shall be governed.

## Monitoring Change Control
Changes to indicators, data sources, coverage, frequency, thresholds, alert routing or monitoring ownership shall be governed, approved, versioned and effective-dated.

```text
CURRENT MONITORING MODEL
↓
CHANGE PROPOSAL
↓

↓
AUTHORITY APPROVAL
↓
NEW VERSION
↓
EFFECTIVE DATE
```

Historical monitoring observations, alerts and material decisions shall remain preserved according to applicable retention and governance requirements.
