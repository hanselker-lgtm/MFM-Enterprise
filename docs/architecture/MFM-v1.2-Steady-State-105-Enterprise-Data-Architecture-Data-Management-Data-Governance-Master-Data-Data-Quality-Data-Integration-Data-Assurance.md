# 1. Purpose

This document establishes the one-hundred-and-fifth document in the MFM v1.2 Steady-State series.

It follows MFM v1.2-Steady-State-104 – Enterprise Application Architecture, Application Portfolio Management, Software Lifecycle, Application Operations & Application Assurance.

The purpose is to establish the permanent enterprise operating model for data architecture, data governance, data ownership, data domains, data lifecycle, master data, reference data, metadata, data quality, data lineage, data integration, data exchange, data stewardship, data classification, data protection integration, data retention integration, data standards, data platforms, data usage, data assurance, data metrics, dashboards, maturity and continual enterprise data capability improvement.

The central objective is:

> **MFM must manage enterprise data as a governed and valuable enterprise asset, ensuring that data is understandable, trustworthy, protected, available, traceable and fit for its intended business purpose throughout its lifecycle.**

# 3. Data Governance Objective

The primary objective is:

> **Establish clear ownership, decision rights, standards, controls and assurance for enterprise data.**

# 4. Data Architecture Objective

The primary objective is:

> **Provide a coherent enterprise data architecture that supports business capabilities, applications, analytics, integration, security, privacy and operational requirements.**

# 5. Data Management Objective

The primary objective is:

> **Ensure enterprise data is created, maintained, used, shared, protected, retained and disposed of in a controlled manner.**

# 6. Data Quality Objective

The primary objective is:

> **Ensure data is sufficiently accurate, complete, consistent, timely, valid, unique and fit for its intended purpose.**

# 7. Data Integration Objective

The primary objective is:

> **Enable reliable and controlled movement and synchronization of data between authorized systems, services and stakeholders.**

# 8. Data Assurance Objective

The primary objective is:

> **Provide evidence that material data controls, quality processes, ownership arrangements and data handling practices remain effective and aligned with enterprise requirements.**

# 121. Definition of Ready

A data architecture, data domain decision, master data change, data integration, data sharing arrangement, quality initiative, retention decision, exception, remediation or assurance review is Ready when purpose, owner, data domain, definitions, classification, dependencies, quality requirements, security and privacy requirements, retention, lifecycle, approval authority and acceptance criteria are defined.

# 122. Definition of Done

```text
Requirement / Need Identified
        ↓

        ↓

        ↓

        ↓
```
