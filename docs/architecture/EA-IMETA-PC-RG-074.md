## Purpose
Establish the authoritative mandatory comparison and deviation-detection layer that converts validated current observations into governed determinations of normality, deviation, regression, uncertainty or measurement failure against the active monitoring baseline.

## Core Principle
An observation becomes governance-relevant only when it is compared with the correct baseline, criteria, thresholds, tolerances and context. Deviation detection shall distinguish ordinary variation from material regression and shall preserve uncertainty where the available evidence cannot support a reliable determination.

```text
VALID OBSERVATION
      ↓
IDENTIFY ACTIVE BASELINE + CONTEXT
      ↓
NORMALIZE / ALIGN COMPARISON
      ↓
COMPARE CURRENT STATE
      ↓
DEVIATION?
├── NO → NORMAL / CONTINUE
├── POSSIBLE → INVESTIGATE / INCREASE OBSERVATION
├── MATERIAL → CLASSIFY / ALERT
└── UNKNOWN → GOVERN EVIDENCE GAP
```

## Comparison Quality Test
```text
VALID CURRENT OBSERVATION
+
CORRECT BASELINE VERSION
+
COMPATIBLE CONTEXT
+
DEFINED CRITERIA
+
VALID THRESHOLDS / TOLERANCES
+
APPROPRIATE COMPARISON METHOD
+
TRACEABLE RESULT
=
VALID GOVERNED COMPARISON
```

## Deviation Quality Test
```text
COMPARISON RESULT
+
EXPECTED STATE
+
MAGNITUDE / DIRECTION
+
DURATION / PERSISTENCE
+
MATERIALITY
+
CONTEXT
+
UNCERTAINTY
=
VALID GOVERNED DEVIATION DETERMINATION
```

```text
NOT COMPARABLE
NORMAL
MINOR DEVIATION
SIGNIFICANT DEVIATION
MATERIAL REGRESSION
PERSISTENT DEVIATION
POSSIBLE REGRESSION
UNKNOWN
INVALID
UNDER INVESTIGATION
```

## Monitoring Comparison Deviation Detection Objective

Determine whether current observed behaviour remains within the intended baseline state and identify meaningful deviation or regression early enough for governed response.

## Monitoring Comparison Deviation Detection Definition

Comparison is the controlled evaluation of current observations against the applicable baseline and criteria. Deviation detection is the governed determination that observed state differs materially or persistently from the expected state.

## Monitoring Comparison Deviation Detection Scope

Scope shall identify systems, services, users, data, decisions, dependencies, environments, consumers and boundaries included in comparison.

## Monitoring Comparison Deviation Detection Authority

Authority shall define who may establish comparison logic, approve thresholds, classify material deviations, challenge results and change detection rules.

## Monitoring Comparison Deviation Detection Criteria

Criteria shall distinguish normal variation, minor deviation, significant deviation, material regression, persistent deviation, possible regression and unknown states.

```text
OBSERVATION
↓
COMPARABLE?
├── NO → UNKNOWN / INVESTIGATE
└── YES
     ↓
WITHIN TOLERANCE?
├── YES → NORMAL
└── NO
     ↓
MATERIAL / PERSISTENT?
├── NO → MINOR DEVIATION
└── YES → SIGNIFICANT / MATERIAL REGRESSION
```

## Monitoring Comparison Deviation Detection Preconditions

Preconditions include validated observation, active baseline, compatible context, approved comparison method, current thresholds and sufficient evidence.

## Monitoring Comparison Deviation Detection Evidence

Evidence shall preserve the source observation, baseline version, comparison inputs, method, threshold logic, result, uncertainty and classification.

## Monitoring Comparison Deviation Detection Method

Methods may include threshold comparison, tolerance-band comparison, trend analysis, rate-of-change analysis, pattern detection, peer comparison and rule-based or statistical detection.

```text
CURRENT OBSERVATION
↓
ALIGN CONTEXT
↓
APPLY COMPARISON METHOD
↓
CALCULATE / DETERMINE DEVIATION
↓
CLASSIFY
```

## Monitoring Comparison Deviation Detection Decision

Comparison results shall remain separate from response decisions. A deviation determination may trigger alerting, but alerting and escalation remain subsequent governed layers.

```text
COMPARISON
↓
DEVIATION
↓
CLASSIFICATION
↓
ALERT WHERE REQUIRED
↓
ESCALATION WHERE REQUIRED
```

## Monitoring Comparison Deviation Detection Accountability

Accountability shall remain explicit for comparison logic, threshold governance, classification, evidence quality and decision traceability.

## Monitoring Comparison Deviation Detection Timing

Detection latency shall reflect time-to-impact and materiality. Faster-changing or higher-impact conditions require more timely comparison.

## Security Monitoring Comparison Deviation Detection

Detect deviations in access, authorization, exposure, control performance, anomalous behaviour and security boundaries against the active security baseline.

## Resilience Monitoring Comparison Deviation Detection

Detect deviations in availability, latency, capacity, recovery capability, continuity, dependency health and degradation against the resilience baseline.

## Compliance Monitoring Comparison Deviation Detection

Detect deviations in obligation status, control operation, evidence completeness, reporting and policy conditions against the compliance baseline.

## Data Monitoring Comparison Deviation Detection

Detect deviations in integrity, quality, completeness, timeliness, lineage, access, retention, authorized use and downstream data behaviour.

## AI and Agent Monitoring Comparison Deviation Detection

Detect deviations in authority use, policy adherence, tool invocation, data access, autonomy, behaviour, configuration and material outcomes.

```text
AI / AGENT OBSERVATION

COMPARE AUTHORITY + POLICY + TOOLS + DATA
↓
COMPARE AUTONOMY + BEHAVIOUR + OUTCOMES
↓
DRIFT / DEVIATION?

└── YES → CLASSIFY / ALERT
```


## Point-in-Time vs Trend Detection
Point-in-time comparison identifies immediate deviation. Trend detection identifies gradual or cumulative movement that may not cross a single threshold but may indicate emerging regression.

```text
POINT-IN-TIME
→ IS IT OUT OF RANGE NOW?

TREND
→ IS THE STATE MOVING TOWARD REGRESSION?
```

## Persistence
Where temporary variation is normal, persistence rules shall prevent a single transient observation from being treated as material regression unless the consequence requires immediate action.

## Aggregation
Repeated minor deviations shall be capable of aggregation where their cumulative effect, frequency or pattern becomes material.

```text
MINOR
+ MINOR
+ MINOR
+ MINOR
      ↓
CUMULATIVE MATERIALITY?
├── NO → CONTINUE
└── YES → MATERIAL CONDITION / ALERT
```

## Direction and Magnitude
Comparison shall consider whether deviation is improving, stable or deteriorating and the magnitude relative to the applicable tolerance or threshold.

## Uncertainty
Where measurement uncertainty is material, classification shall account for uncertainty rather than presenting an uncertain result as a definitive deviation or normal state.

## Baseline Version Integrity
Every comparison shall identify the baseline version used. Historical comparisons shall remain linked to the baseline that was active at the relevant time.

## Threshold Change Control
Changes to thresholds, tolerances, comparison logic, persistence windows, aggregation rules or classification criteria shall be governed and versioned.

```text
CURRENT DETECTION LOGIC
↓
CHANGE PROPOSAL
↓
IMPACT / FALSE-POSITIVE / FALSE-NEGATIVE ASSESSMENT
↓
APPROVAL
↓
NEW VERSION
```

## Detection Anti-Gaming
Detection logic shall not be weakened merely to reduce alert volume, avoid escalation, preserve performance metrics or normalize degraded behaviour.

## False Positive / False Negative Balance
Detection governance shall consider both false positives and false negatives. Excessive false positives can cause alert fatigue; excessive false negatives can allow regression to persist unnoticed.

## Alert Handoff
A classified material deviation shall provide sufficient evidence and context for the subsequent alerting layer to act without reconstructing the entire comparison manually.

```text
DEVIATION CLASSIFIED
↓
EVIDENCE + CONTEXT + BASELINE + THRESHOLD
↓
ALERT
```
