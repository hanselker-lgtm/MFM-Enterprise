## Purpose
Establish the authoritative mandatory baseline against which restored reliance is monitored, compared and judged for regression after reliance has been restored.

## Core Principle
A restored state cannot be monitored for regression without an explicit current baseline. The baseline shall represent the accepted and operationally restored state, including scope, conditions, dependencies, expected behaviour, performance, controls, risks and measurement context. The baseline is a governed reference point, not an assumption.

```text
RESTORED RELIANCE
      ↓
CONFIRM CURRENT STATE
      ↓
DEFINE BASELINE SCOPE + CONDITIONS
      ↓
CAPTURE EXPECTED STATE + MEASUREMENTS
      ↓
VALIDATE BASELINE
      ↓
BASELINE ACCEPTED?
├── YES → ACTIVATE MONITORING
├── CONDITIONAL → MONITOR WITH CONDITIONS
└── NO → HOLD / CORRECT / RE-ESTABLISH
```

## Reliance Restoration Monitoring Baseline Objective

Create a stable, explicit and measurable reference point from which post-restoration monitoring can identify meaningful deviation and regression.

## Reliance Restoration Monitoring Baseline Definition

A monitoring baseline is the governed representation of the accepted restored state against which subsequent observations are compared for stability, deviation and regression.

## Reliance Restoration Monitoring Baseline Scope

Scope shall identify systems, services, users, data, decisions, dependencies, environments, consumers and boundaries represented by the baseline.

## Reliance Restoration Monitoring Baseline Authority

Authority shall define who may establish, validate, accept, change, supersede or invalidate the baseline.

## Reliance Restoration Monitoring Baseline Criteria

Criteria shall distinguish captured, validated, accepted, conditional, active, superseded and invalidated baselines.

```text
RESTORED STATE
↓
CURRENT + COMPLETE?
├── NO → CORRECT / HOLD
└── YES
     ↓
MEASURABLE EXPECTED STATE?
├── NO → DEFINE
└── YES
     ↓
THRESHOLDS + DEPENDENCIES VALID?
├── NO → CORRECT
└── YES → ACCEPT BASELINE
```

## Reliance Restoration Monitoring Baseline Preconditions

Preconditions include current reliance restoration, reacceptance traceability, defined scope, expected state, indicators, thresholds, tolerances, dependencies and baseline authority.

## Reliance Restoration Monitoring Baseline Evidence

Evidence shall demonstrate the actual restored state at baseline establishment, including relevant measurements, configurations, controls, conditions and dependencies.

## Reliance Restoration Monitoring Baseline Method

Methods may include snapshot, measurement, configuration capture, behavioural profiling, control-state capture, sampling and dependency-state recording.

```text
RESTORED STATE
↓
CAPTURE
↓
MEASURE
↓
VALIDATE
↓
VERSION
↓
ACCEPT
```

## Reliance Restoration Monitoring Baseline Decision

Decisions shall distinguish accept, conditional accept, hold, reject, supersede and invalidate.

```text
ACCEPT → ACTIVE BASELINE
CONDITIONAL → ACTIVE WITH CONDITIONS
HOLD → NOT ACTIVE
REJECT → REBUILD
SUPERSEDE → NEW VERSION
INVALIDATE → STOP RELIANCE COMPARISON / REASSESS
```

## Reliance Restoration Monitoring Baseline Accountability

Accountability shall remain explicit for baseline completeness, validity, acceptance, changes, thresholds and historical integrity.

## Reliance Restoration Monitoring Baseline Timing

Baseline establishment shall occur at or immediately around restoration while the restored state is current and observable. Significant delay shall require explicit justification.

## Security Reliance Restoration Monitoring Baseline

Baseline security state shall capture material access, authorization, exposure, boundaries, control status and expected security behaviour.

## Resilience Reliance Restoration Monitoring Baseline

Baseline resilience state shall capture availability, capacity, recovery capability, continuity, dependencies and expected resilience behaviour.

## Compliance Reliance Restoration Monitoring Baseline

Baseline compliance state shall capture applicable obligations, controls, evidence, reporting and required policy conditions.

## Data Reliance Restoration Monitoring Baseline

Baseline data state shall capture integrity, quality, lineage, access, retention, authorized use and relevant downstream expectations.

## AI and Agent Reliance Restoration Monitoring Baseline

Baseline AI/agent state shall capture authority, policy, tools, data boundaries, autonomy, expected behaviour, configuration and material outcomes.

## Baseline vs Snapshot
A snapshot records observations at a point in time. A governed baseline additionally defines expected state, scope, indicators, thresholds, conditions, dependencies, authority and versioning for future comparison.

```text
SNAPSHOT
→ WHAT WAS OBSERVED?

BASELINE
→ WHAT IS THE GOVERNED EXPECTED STATE AGAINST WHICH WE COMPARE?
```

## Baseline Stability
The baseline should represent a stable and intended restored state. Temporary transition behaviour shall not silently become the normal reference condition.

## Baseline Measurement Context
Measurements shall preserve relevant units, time window, sampling method, environment, configuration and context necessary for meaningful future comparison.

```text
MEASUREMENT
+
TIME WINDOW
+
METHOD
+
ENVIRONMENT
+
CONFIGURATION
+
CONTEXT
=
COMPARABLE BASELINE EVIDENCE
```

## Thresholds and Tolerances
Thresholds determine material deviation boundaries; tolerances define permitted normal variation. Both shall be explicit where used and shall not be altered merely to reduce observed regression.

## Dependency Baseline
Dependencies material to restored reliance shall have their expected state or acceptable condition represented where changes could affect regression interpretation.

## Baseline Versioning
Every active baseline shall have an immutable identity and effective time. Changes shall create a governed new version rather than silently rewriting history.

```text
BASELINE vN
↓
CHANGE REQUIRED
↓
ASSESS IMPACT
↓
APPROVE
↓
BASELINE vN+1
↓
PRESERVE vN
```

## Rebaselining
Rebaselining is permitted only when the intended current state has legitimately changed and the change is governed. It shall not be used to redefine regression away.

```text
OBSERVED DEVIATION
↓
EXPECTED STATE ACTUALLY CHANGED?
├── NO → REGRESSION
└── YES → GOVERNED REBASELINE ASSESSMENT
```

## Baseline Anti-Gaming
Baseline values, thresholds, tolerances and scope shall not be manipulated to hide degradation, reduce alerts, avoid escalation or preserve operational metrics.

## Monitoring Activation
Once the baseline is accepted, the monitoring regime shall activate against that baseline and preserve the link between each observation and the baseline version used for comparison.

## Relationship to Alerting and Escalation
Baseline establishment precedes meaningful regression alerting. Alert thresholds shall be traceable to the active baseline and its governing criteria.

```text
BASELINE
↓
OBSERVE
↓
COMPARE
↓
DEVIATION
↓
ALERT
↓
ESCALATE
```
