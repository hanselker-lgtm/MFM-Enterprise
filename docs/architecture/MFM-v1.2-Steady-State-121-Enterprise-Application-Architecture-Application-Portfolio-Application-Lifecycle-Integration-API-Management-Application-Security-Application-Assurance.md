# 1. Purpose

This document establishes the one-hundred-and-twenty-first document in the MFM v1.2 Steady-State series.

It follows MFM v1.2-Steady-State-120 – Enterprise Data Architecture, Data Governance, Data Management, Data Quality, Data Security, Data Lifecycle & Data Assurance.

The purpose is to establish the permanent enterprise operating model for application strategy, application governance, application ownership, application portfolio management, application architecture, application lifecycle, application standards, application integration, APIs, application dependencies, application environments, application deployment, application monitoring, application performance, application security, application vulnerability management, application incidents, application changes, application releases, application resilience, application continuity, application suppliers, application compliance, application exceptions, remediation, application assurance, metrics, dashboards, maturity and continual enterprise application capability improvement.

The central objective is:

> **MFM must govern applications as controlled enterprise capabilities, ensuring that applications are appropriately owned, architected, secured, integrated, monitored, maintained, resilient and lifecycle-controlled in alignment with business requirements and enterprise architecture.**

# 3. Application Governance Objective

The primary objective is:

> **Establish clear authority, ownership, architecture standards, lifecycle controls, security requirements, operational responsibilities and assurance for enterprise applications.**

# 4. Application Architecture Objective

The primary objective is:

> **Provide a coherent application landscape aligned with business capabilities, data, integration, identity, infrastructure, cloud, security and service-management requirements.**

# 5. Application Portfolio Objective

The primary objective is:

> **Maintain an accurate, governed and decision-useful portfolio of applications, their ownership, dependencies, costs, risks, lifecycle states and strategic relevance.**

# 6. Application Integration Objective

The primary objective is:

> **Provide controlled, secure, observable and maintainable application integration through approved interfaces, APIs, events, messaging and data exchange mechanisms.**

# 7. Application Security Objective

The primary objective is:

> **Protect applications, interfaces, identities, data and application environments against unauthorized access, vulnerabilities, misuse and compromise throughout the application lifecycle.**

# 8. Application Assurance Objective

The primary objective is:

> **Critical applications must have resilience, continuity, backup and recovery capabilities aligned with business impact and validated through appropriate testing.**
