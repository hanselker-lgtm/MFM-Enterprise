## Purpose
Establish the authoritative mandatory-threshold layer defining the boundaries used to interpret measurements of applicable mandatory states. The layer governs threshold purpose, definition, scope, authority, baselines, boundaries, classifications, calculations, quality, uncertainty, timing, breaches, escalation and review.

## Core Principle
A threshold is a governed decision boundary. It defines when a measured or assessed condition is considered acceptable, at risk, failed or otherwise requiring action. Thresholds shall not be selected merely for convenience or adjusted after an adverse result to avoid a failure determination.

```text
MANDATORY MEASUREMENT
        ↓
THRESHOLD DEFINITION
        ↓
BASELINE / BOUNDARY
        ↓
MEASUREMENT RESULT
        ↓
CLASSIFY
        ↓
NORMAL / WARNING / FAILURE / CRITICAL
        ↓
REQUIRED RESPONSE
```

## Threshold Structure

| Element | Required definition |
|---|---|
| State | Mandatory state being protected |
| Measurement | Measurement interpreted |
| Threshold | Decision boundary |
| Source | Authority / rationale |
| Baseline | Reference state/value |
| Boundary Logic | Comparison rule |
| Classification | Normal, warning, failure, critical etc. |
| Response | Required action |
| Effective Date | Start of applicability |
| Version | Governing threshold version |
| Exception | Authorized exception mechanism |

## Threshold Objective

The threshold objective shall state what decision the threshold is intended to support and what risk or state boundary it protects.

```text
MANDATORY STATE
↓
MEASUREMENT
↓
THRESHOLD OBJECTIVE
↓
DECISION BOUNDARY
```

## Threshold Definition

Threshold definitions shall specify value, range, condition, directionality, units, comparison logic and interpretation. Qualitative thresholds shall define observable decision criteria.

## Threshold Scope

Scope shall identify the systems, services, controls, processes, environments, data, populations and lifecycle conditions to which the threshold applies.

## Threshold Authority

Threshold authority shall identify who may approve, modify, suspend or retire a threshold. Operational users shall not alter thresholds without authorized governance.

## Threshold Baseline

Baselines provide the reference against which threshold boundaries are interpreted. Baselines shall have provenance, version, effective date and change rationale.

## Threshold Boundary

Boundaries shall be explicit and unambiguous.

```text
MEASURED VALUE
      ↓
COMPARE
      ↓
BOUNDARY
 ├── BELOW
 ├── WITHIN
 ├── ABOVE
 └── CRITICAL / EXCEPTIONAL
```

## Threshold Classification

Classification shall define the meaning and response associated with each threshold range.

```text
NORMAL → CONTINUE
WARNING → MONITOR / ACT
FAILURE → BLOCK / REMEDIATE
CRITICAL → CONTAIN / ESCALATE
```

## Threshold Calculation

Where thresholds depend on calculations, the formula, input sources, units, rounding, aggregation and validation rules shall be defined.

## Threshold Quality

Threshold quality shall consider whether the boundary is meaningful, stable, risk-aligned, testable and based on adequate evidence.

## Threshold Uncertainty

Where measurement uncertainty could change classification, the uncertainty treatment shall be explicit. Uncertainty shall not be manipulated to obtain a preferred classification.

```text
RESULT + UNCERTAINTY
        ↓
CLASSIFICATION RULE
        ↓
DETERMINATION
```

## Threshold Timing

Thresholds may vary by time, lifecycle state, operating mode or event condition. Timing rules shall be explicit and version controlled.

## Security Thresholds

Security thresholds may govern vulnerabilities, exposure, failed authentication, access anomalies, availability, integrity indicators, incident severity or control effectiveness. Threshold breaches shall trigger defined security responses.

## Resilience Thresholds

Resilience thresholds may govern recovery performance, restoration time, capacity, dependency availability, continuity readiness and degraded-operation limits.

## Compliance Thresholds

Compliance thresholds shall define boundaries for acceptable conformity where quantitative or categorical limits are meaningful. A threshold shall not weaken an underlying mandatory legal or governance obligation.

## Data Thresholds

Data thresholds may govern accuracy, completeness, timeliness, integrity, consistency, availability, lineage or authorized-use conditions.

## AI and Agent Thresholds

AI and agent thresholds shall protect mandatory authority, safety, policy and operational boundaries. Thresholds may govern confidence, intervention, exception, unsafe-action, tool-use or autonomy indicators where appropriate.

```text
AI / AGENT MEASUREMENT
        ↓
THRESHOLD
        ↓
WITHIN AUTHORITY / SAFETY BOUNDARY?
 ├── YES → CONTINUE
 └── NO  → BLOCK / ESCALATE
```

## Threshold Breach

A threshold breach occurs when the governed classification rule determines that the measured state has crossed an applicable boundary.

```text
MEASUREMENT
   ↓
THRESHOLD BREACH
   ↓
CLASSIFY
   ↓
BLOCK / CONTAIN / REMEDIATE / ESCALATE
```

## Threshold Escalation

Material, systemic, persistent or critical threshold breaches shall be escalated according to defined authority. Repeated warning states shall be reviewed where they indicate emerging regression.

## Threshold Review and Learning

Thresholds shall be reviewed after incidents, repeated breaches, false alarms, missed regressions, material risk changes, architecture changes, changed measurement methods or evidence that the boundary no longer protects the intended state.

## Threshold Determination Model
```text
MEASUREMENT
↓
THRESHOLD VERSION VALID?
├── NO → UNDETERMINED / ESCALATE
└── YES
     ↓
MEASUREMENT QUALITY SUFFICIENT?
├── NO → UNDETERMINED / LIMITED
└── YES
     ↓
COMPARE WITH BOUNDARY
     ↓
CLASSIFY
 ├── NORMAL
 ├── WARNING
 ├── FAILURE
 └── CRITICAL
```

## Threshold Anti-Gaming Control
Thresholds shall not be changed, widened, delayed, reclassified or retrospectively redefined for the purpose of avoiding an adverse determination. Any proposed change shall follow normal governance and shall apply prospectively according to its effective date.

## Threshold Change Control
```text
CURRENT THRESHOLD
      ↓
CHANGE PROPOSAL
      ↓
IMPACT / RISK ASSESSMENT
      ↓
AUTHORITY APPROVAL
      ↓
NEW VERSION
      ↓
EFFECTIVE DATE
```

Historical measurements shall remain associated with the threshold version that governed their original determination.
