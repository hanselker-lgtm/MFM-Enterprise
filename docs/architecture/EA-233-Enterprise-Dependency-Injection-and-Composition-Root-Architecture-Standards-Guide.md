# 1. Purpose

The purpose of this document is to define the mandatory standards governing Enterprise Dependency Injection & Composition Root throughout the MFM Enterprise Platform.

Enterprise Dependency Injection & Composition Root provides standardized mechanisms for dependency management, object composition, service registration and lifecycle control while preserving loose coupling, maintainability, testability and compliance with Enterprise Architecture.

---

# 2. Scope

This guide applies to

- Dependency Injection
- Composition Root
- Service Registration
- Dependency Resolution
- Lifetime Management
- Dependency Validation
- Governance
- Compliance

All Enterprise Dependency Injection & Composition Root implementations shall comply with this guide.

# 4. Enterprise Dependency Injection Principles

Enterprise Dependency Injection & Composition Root implementations shall follow these principles.

- Constructor Injection by Default
- Single Composition Root
- Explicit Dependency Registration
- Controlled Lifetime Management
- Dependency Validation
- Technology Independence
- Centralized Governance
- Separation of Concerns

Enterprise Dependency Injection implementations shall remain independent of business logic.

Enterprise Dependency Injection & Composition Root implementations shall implement a standardized Composition Root.

The Composition Root shall

- centralize dependency registration
- centralize object composition

# 25. Common Anti-Patterns

The following practices are prohibited.

## Multiple Composition Roots

Enterprise applications shall never contain multiple independent Composition Roots within the same deployable application.

---

## Service Locator Pattern

Enterprise implementations shall never use the Service Locator pattern as a substitute for explicit dependency injection.

---

## Hidden Dependencies

Enterprise components shall never conceal required dependencies through static access, global state or implicit initialization.

---

## Circular Dependencies

Enterprise dependency graphs shall never contain circular dependencies between services or components.

---

## Manual Object Construction

Enterprise applications shall never instantiate managed services manually outside the approved Composition Root unless explicitly approved by Enterprise Architecture.

---

## Business Logic Inside Dependency Injection Infrastructure

Enterprise Dependency Injection & Composition Root implementations shall never contain business logic that belongs within the appropriate Domain or Capability implementation.

# Final Statement

The Enterprise Dependency Injection & Composition Root Architecture Standards Guide defines the mandatory standards governing Enterprise Dependency Injection & Composition Root throughout the MFM Enterprise Platform.

Its purpose is to ensure that dependency registration, composition, dependency resolution and lifecycle management are implemented consistently while preserving loose coupling, maintainability, testability and compliance with Enterprise Architecture.

All Enterprise Dependency Injection & Composition Root implementations developed for the MFM Enterprise Platform shall comply with this guide.
