# 1. Purpose

This document establishes the fortieth document in the MFM v1.2 Steady-State series.

It follows MFM v1.2-Steady-State-39 – Enterprise Data Management, Data Governance, Data Architecture, Data Quality, Master Data, Analytics & Information Management.

The purpose of this document is to establish the permanent enterprise operating model for cybersecurity, information security, security governance, identity and access management, security architecture, security risk, security controls, security operations, security monitoring, security incident management, vulnerability management, security configuration, security awareness, privileged access, authentication, authorization, cryptography, security logging, threat management, security assurance, third-party security, cloud security, application security, infrastructure security, data security, security continuity and continual security improvement.

The central objective is:

> **MFM must protect its information, technology, applications, infrastructure, identities, services and business operations through a risk-based, continuously governed cybersecurity and information-security operating model.**

# 128. Final Cybersecurity Governance Principle

> **Cybersecurity must be governed as an enterprise risk and business-enablement capability with clear accountability, controls, evidence and continuous improvement.**

---

# 129. Final Information Security Principle

> **Information and supporting technology must be protected according to confidentiality, integrity, availability, authenticity and accountability requirements.**

---

# 130. Final Identity Principle

> **Every material identity must be appropriately established, authenticated, authorized, monitored and removed when its legitimate need ends.**

---

# 131. Final Least-Privilege Principle

> **Access must be limited to the minimum privileges necessary to perform authorized responsibilities.**

---

# 132. Final Security Operations Principle

> **Security operations must continuously monitor, detect, investigate, respond to and learn from security events and threats.**

---

# 133. Final Vulnerability Principle

> **Material vulnerabilities must be identified, risk-prioritized, remediated and validated within appropriate timeframes.**

---

# 134. Final Security-by-Design Principle

> **Security must be integrated from strategy and architecture through implementation, operation, change and retirement.**

---

# 135. Final Third-Party Security Principle

> **Third-party security risk must be governed throughout supplier selection, onboarding, operation, monitoring and exit.**

---

# 136. Final Resilience Principle

> **MFM must maintain the capability to securely recover critical services following cyber disruption or security incidents.**

---

# 137. Final Assurance Principle

> **Material security controls must be supported by evidence and periodically assessed for design, implementation and operating effectiveness.**

---

# 138. Final Improvement Principle

> **Threat intelligence, incidents, vulnerabilities, findings, control assessments, audit results, technology changes and operational lessons must continuously improve MFM security capability.**

---

# 139. Final Integration Principle

> **Cybersecurity and Information Security must integrate with Enterprise Architecture, Application Management, Infrastructure, Data Management, Privacy, Service Management, Financial Management, Procurement, Supplier Management, People Management, Business Continuity, Risk, Compliance and Project Management.**

---

# 140. Final Steady-State Security Principle

> **MFM must protect its information, technology, applications, infrastructure, identities, services and business operations through a risk-based, continuously governed cybersecurity and information-security operating model.**
