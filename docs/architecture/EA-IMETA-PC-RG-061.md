## Purpose
Establish the authoritative mandatory revalidation layer defining how a verified resolution state is reassessed against current conditions, criteria, dependencies, boundaries and evidence to determine whether the verified state remains valid for continued governance progression.

## Core Principle
Verification establishes that a required state was demonstrated at a defined point and scope; revalidation establishes whether that verified state remains currently valid. Verification and revalidation shall therefore remain distinct governance determinations.

```text
VERIFIED RESOLUTION STATE
      ↓
DEFINE CURRENT VALIDITY CONDITIONS
      ↓
REASSESS TIME + SCOPE + DEPENDENCIES + CONTEXT
      ↓
COMPARE CURRENT STATE WITH VERIFIED BASELINE
      ↓
REVALIDATION RESULT
├── VALID → REACCEPTANCE PATH
├── CONDITIONAL → CONTROL + MONITOR
├── PARTIAL → REASSESS / REMEDIATE
├── INVALID → REOPEN / REVERIFY
└── UNKNOWN → COMPLETE EVIDENCE
```

## Revalidation Quality Test
```text
VERIFIED STATE
+
CURRENT VALIDITY CRITERIA
+
CURRENT EVIDENCE
+
CHANGE / DRIFT ASSESSMENT
+
DEPENDENCY REVIEW
+
BOUNDARY REVIEW
+
RESIDUAL-RISK REVIEW
+
AUTHORIZED DETERMINATION
=
VALID GOVERNED REVALIDATION
```

## Verification Revalidation Structure

| Element | Required definition |
|---|---|
| Verified State | Previously verified state |
| Current Validity Criteria | Conditions for continued validity |
| Current State | Present observed state |
| Change / Drift | Material differences since verification |
| Dependencies | Current relevant dependencies |
| Boundaries | Current applicable limits |
| Determination | Revalidation result |
| Follow-on | Reaccept / condition / reopen |

## Verification Revalidation Objective

Determine whether a previously verified resolution remains currently valid and suitable for progression to reacceptance or continued controlled reliance.

## Verification Revalidation Definition

Revalidation is the governed reassessment of a previously verified state against current conditions, criteria, evidence, dependencies and boundaries.

## Verification Revalidation Scope

Scope shall identify systems, services, users, data, decisions, dependencies, environments, time period and boundaries included in the revalidation.

## Verification Revalidation Authority

Authority shall define who may perform, review, challenge and approve revalidation and who may require reopening or additional evidence.

## Verification Revalidation Criteria

Criteria shall distinguish valid, conditional, partial, invalid and unknown states.

```text
VERIFIED STATE
↓
CURRENT CRITERIA VALID?
├── NO → GOVERNANCE GAP
└── YES
     ↓
MATERIAL CHANGE / DRIFT?
├── YES → ASSESS IMPACT
└── NO → CONTINUE
     ↓
CURRENT EVIDENCE SUFFICIENT?
├── NO → UNKNOWN
└── YES
     ↓
STATE STILL VALID?
├── NO → INVALID / REOPEN
└── YES → REVALIDATED
```

## Verification Revalidation Preconditions

Preconditions include a valid verified baseline, current criteria, defined review period or trigger, current evidence, scope, authority and applicable change information.

## Verification Revalidation Evidence

Evidence shall demonstrate current validity and identify material changes, drift, dependency changes, boundary changes and residual-risk conditions.

## Verification Revalidation Method

Methods may include periodic review, triggered reassessment, comparative testing, trend analysis, dependency review, control review and current-state observation.

```text
VERIFIED BASELINE
↓
CURRENT STATE
↓
COMPARE
↓
CHANGE / DRIFT ASSESSMENT
↓
DETERMINE VALIDITY
```

## Verification Revalidation Decision

Decisions shall distinguish revalidated, conditionally revalidated, partially revalidated, invalid and unknown outcomes.

```text
VALID → REACCEPTANCE PATH
CONDITIONAL → CONTROL + MONITOR
PARTIAL → COMPLETE / REASSESS
INVALID → REOPEN / REVERIFY
UNKNOWN → COMPLETE EVIDENCE
```

## Verification Revalidation Accountability

Accountability shall remain explicit for current-state assessment, change analysis, determination, conditions and follow-on decisions.

## Verification Revalidation Timing

Revalidation timing shall reflect materiality, change rate, volatility, dependency sensitivity, time-to-impact and defined validity periods. Overdue revalidation shall be visible.

## Security Verification Revalidation

Revalidate security assumptions, access, exposure, controls, threats, boundaries and relevant security outcomes against current conditions.

## Resilience Verification Revalidation

Revalidate availability, recovery capability, continuity, capacity, dependencies and resilience assumptions against current conditions.

## Compliance Verification Revalidation

Revalidate obligations, controls, policies, reporting requirements and evidence against current regulatory and governance conditions.

## Data Verification Revalidation

Revalidate data integrity, quality, lineage, access, retention, authorized use and material downstream dependencies.

## AI and Agent Verification Revalidation

Revalidate AI/agent authority, policy, tools, data boundaries, autonomy, behaviour and material outcomes against current operating conditions.

```text
VERIFIED AI / AGENT
↓
CURRENT AUTHORITY + POLICY + TOOLS + DATA + AUTONOMY + BEHAVIOUR
↓
STILL VALID?
├── YES → REVALIDATED
└── NO → RESTRICT / REOPEN / REVERIFY
```

## Verification Revalidation Failure

Failure includes material drift, changed dependencies, invalid assumptions, expired validity, insufficient current evidence or changed criteria.

```text
REVALIDATION FAILURE
↓
NO UNCONTROLLED PROGRESSION
↓
RESTRICT / REOPEN
↓
REMEDIATE / REVERIFY
↓
REVALIDATE AGAIN
```

## Verification Revalidation Independence

Where materiality requires it, revalidation shall receive independent challenge or review separate from the original remediation and verification roles.

## Verification Revalidation Review and Learning

Reviews shall identify recurring drift, stale assumptions, inadequate validity periods, missed triggers and opportunities to improve revalidation design.

## Change and Drift Assessment
Material change shall be evaluated across technology, process, people, data, dependencies, threat environment, regulation, operating context and expected outcomes where applicable.

```text
VERIFIED BASELINE
↓
WHAT CHANGED?
├── NOTHING MATERIAL → CONTINUE
└── MATERIAL CHANGE
     ↓
IMPACT ON VALIDITY?
├── NO → DOCUMENT
└── YES → REVALIDATE / REVERIFY / REOPEN
```

## Validity Periods
Where a defined validity period exists, expiry shall be explicit. Expiration shall not be silently extended by continued use.

## Triggered Revalidation
Material events may trigger revalidation before the normal review point, including major change, incident, dependency failure, regulatory change, significant drift, new threat or material outcome deviation.

```text
TRIGGER EVENT
↓
REVALIDATION DUE
↓
ASSESS CURRENT VALIDITY
↓
REVALIDATED / CONDITIONAL / INVALID
```

## Overdue Revalidation
Overdue revalidation shall remain visible and shall have a governed disposition. Where current validity cannot reasonably be assumed, reliance may require restriction or suspension.

## Revalidation vs Reacceptance
Revalidation determines whether the state remains valid. Reacceptance determines whether the authorized authority formally accepts that current state. They shall not be collapsed into one decision.

```text
VERIFY → IS IT DEMONSTRATED?
REVALIDATE → IS IT STILL VALID?
REACCEPT → DO WE FORMALLY ACCEPT IT NOW?
```

## Revalidation Change Control
Changes to criteria, scope, validity periods, triggers, evidence, methods or authority shall be governed, approved, versioned and effective-dated.

```text
CURRENT REVALIDATION MODEL
↓
CHANGE PROPOSAL
↓
IMPACT / RISK ASSESSMENT
↓
AUTHORITY APPROVAL
↓
NEW VERSION
↓
EFFECTIVE DATE
```

## Revalidation Anti-Gaming Control
Revalidation shall not be used to preserve a historical verification simply by ignoring material change, redefining scope without governance or extending validity without explicit authorization.

Historical revalidation records, baseline versions, current-state evidence, change assessments, conditions, failures, overdue states and follow-on decisions shall remain preserved according to applicable retention and governance requirements.
